# ANR 报告验收与交付

## 范围与边界

实现统一的报告交付验收，保留四个 AI 槽位、每 ANR 独立重建和完整 JSON。
`analysisComplete` 继续仅表示四槽位已填写；`deliveryReadiness` 由规则计算，不由模型授权。
报告可交付、根因确认、修复验证是不同证据层。所有候选仍保持保守标志。
不增加第三方依赖，不执行设备操作，不提交或推送，不恢复其他工作流删除的文件。

## 就绪状态

- `blocked`：结构、身份、支撑引用、版本或产物有硬错误。
- `needs_review`：机器检查通过，但指定的关键断言尚需复核。
- `ready_with_limitations`：缺口已披露、相关断言已收敛，可带限制交付。
- `ready`：当前规则全部必需项通过，无已声明的重大交付限制。

状态优先级：阻断项 > 待复核项 > 限制项 > 就绪。
未执行的必需检查不能视为通过。任何状态都不授予最终根因裁决权。
缺来源或没有确定根因不自动阻断；无效引用若仍支撑当前结论则阻断。
未决补探须记录停止原因，不能悄悄当作成功，也不能无限重试。

## 数据与接口

`report_validation.py` 提供无文件写入的共享内核、严格 JSON 解析、内容摘要和三条路径的薄适配。
`acceptance.py` 负责已有工作区的安全读取、只读验收与最终交付回执。
模型、Phase 包和 Markdown 各用自己的最低结构，不强迫内存报告满足四槽位或磁盘产物要求。

每组 `acceptance.json` 记录 `policyVersion`、`groupId`、证据版本、分析摘要、产物内容摘要、
检查结果、阻断项、待复核项和警告。`index.json` 只聚合各组就绪度与路径。
回执和索引不进入自身摘要；修改证据、分析或依赖产物使旧回执失效。
仅排版变化需要重新验收，不直接判定结论过期；规则变化触发重新验收。
复核记录绑定具体问题、证据版本及分析摘要，不接受模型 JSON 中的自报通过。

只读预检的 `deliverable` 表示门槛合格，`finalized` 另行表示有内容完全匹配的成功回执。
旧结论重审须实质更新正文，并通过最终 JSON 的 `evidenceRevision` 绑定当前证据；
复制旧结论或只改排版不能清除 stale 状态，新的内容仍为未验证候选。
外部复核为调用者提供的逐问题声明，不声称密码学身份认证；无效或阻断回执不能复用复核。

Phase 路径在 Phase 3 建立 `evidenceCatalog`/身份/摘要，经 Phase 5、6、7 保留；
旧包仅片段的兼容边界明确警告，不用新增片段覆盖已有可信证据清单。
类型规则检查非输入类型的输入事件误判、无焦点/ACK 分支混用、序号域、
JobService 完成与回调返回混淆，以及结构化模型的跨时钟时长和快照持续性断言。

## 交付顺序

草稿提取与刷新继续允许待填状态。正式 finalize 必须：

1. 冻结当前事故身份、证据及分析内容。
2. 校验证据版本，刷新重建但不修改 AI 槽位。
3. 在同一内容快照上检查结构、引用、保守策略和重建同步。
4. 重新核对依赖文件；中途变化则拒绝写出成功回执。
5. 原子写出各组回执，最后更新索引；只交付通过组，明确列出其余组。

## 首批回归场景

- 四个单句、模板、空 JSON、重复槽位、代码围栏内假标题均不能伪装完成。
- 引用不存在、不唯一、跨 ANR 或错误版本的证据不能支撑结论。
- 证据变化旧结论未审、分析变化重建未刷、产物变化或缺文件导致阻断。
- 缺 Trace/根因未知但缺口明确且结构合格的报告可带限制交付。
- 三个保守标志错误、模拟候选宣称已执行或已验证不能通过。
- Manager 空对象、非法 JSON、重复键/非有限数字、最后一轮补探必须显式处理。
- 多 ANR 部分失败不掩盖，多路径适配结果保持候选性质。
- 回执不能重放到另一组或新内容；复核不能绕过硬错误。
